# Editorial policy

## Trust and scoring
Statements must be split into (a) confirmed change (b) supported inference (c) opinion (d) unverified rumor. For consequential claims, include claim text, evidence URL, evidence excerpt <= permitted quote limit, checked_at, verification type, counter-source and risk. `confidence=high` only after independent verification; source link existence alone is insufficient.

## Publishing rules
Low-risk straightforward official release with valid schema/grounding MAY qualify for auto-publication only after tests and editorial policy approved. Default MVP must publish drafts via human editor. High-impact changes to API, prices, data handling, licensing, security, critical vulnerabilities, model IDs, migration and comparative benchmarks ALWAYS need human approval. Review tied to immutable revision; edits after approval reset to review. Model cannot directly publish; tool dispatcher refuses. No minimum quota of articles per day.

## Copyright and tone
Create original synthesis with attribution; no mass copying publisher text/images without license; clear Vietnamese, specific dev implications, uncertainty, source priority, not hype. Reject content farms, SEO keyword stuffing, invented screenshots, model rankings without comparable eval. Quotes brief and within rights policy.

## Correction & takedown
Public corrections show reason, date, revision and source. Article correction never silently hides misinformation history from admin audit. Implement user report and request-for-removal path, remove caches/search references when unpublished.
